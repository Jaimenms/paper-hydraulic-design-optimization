# Architecture

```
src/cwnet/
├── model/          pydantic data model: DesignCase (root), Network/Node/Edge, PipeSection, PipeCatalog,
│                   PumpCurve/PumpUnit, HeatExchanger (+ThermalDesign), Economics, Scenario, DesignOptions
├── io/             YAML/JSON load/save (yaml_io.py) and the legacy Scilab text format (scilab_legacy.py)
├── topology/       incidence / classification / selection / circuit matrices (incidence.py), mass balance
├── hydraulics/     Churchill friction factor, head-loss tables per scenario (HydraulicTables)
├── costs/          Narang pipe cost and revamp cost matrix, Couper pump cost, operating cost
├── design/         traditional.py (economic velocity), lp.py (split-pipe LP per pump, HiGHS),
│                   postprocess.py (optional QP), evaluate.py (simulation + costs), optimizer.py
│                   (run_design_study), results.py (NetworkDesign, DesignStudy, CostBreakdown), sensitivity.py
├── simulation/     network_sim.py (Newton simulation of the designed network), thermal.py (ε-NTU check)
├── reporting/      tables.py (pandas tables of the papers), plots.py (figures), evaluation.py (`eval`),
│                   export.py (`run` and `figures` outputs)
├── references.py   paper references, paper cases, published values loader
└── cli.py          `cwnet` command line (info, validate, run, eval, figures, simulate, convert-legacy)
cases/              YAML cases of the papers (+ legacy/ conversions of the Scilab cases)
data/reference/     published values (published_values.json)
legacy/scilab, legacy/gams   original Scilab code (v1-v2.2) and the GAMS sketch of the LP
notebooks/          executed notebooks, generated by scripts/build_notebooks.py
```

## Design decisions

* **Data first.** A `DesignCase` holds every parameter, including the digraph, and validates it
  (unique ids, one supply and one demand node, every edge assigned to a pipe/pump/exchanger, flow
  specification for every exchanger in every scenario). Everything else is a pure function of the case.
* **Matrix formulation kept explicit.** `NetworkTopology` exposes `K`, `u_PS`, `u_PD`, `Ψ_PI`, `Ψ_PU`,
  `Ψ_HE`, `E` and `Λ` with the names of the paper so that the notebooks can show them.
* **Precomputed hydraulics.** Head losses of every pipe for every catalogue diameter and scenario are
  tabulated once (`HydraulicTables`); the LP only assembles coefficients.
* **One LP per pump alternative**, enumerated and ranked by total cost (equivalent to the MILP of the
  2016 paper). The LP is solved by HiGHS (dual simplex) through SciPy; the vertex returned is one of the
  alternative optima, so results are compared by cost and by length per diameter along series groups.
* **Verification by simulation.** Every design (traditional or LP) is simulated rigorously (mass and
  mechanical-energy balances solved by Newton), and the operating cost uses the simulated operating
  point; balanced LP designs reproduce the specified flows exactly, unbalanced traditional designs do not.
* **Published vs consistent conventions as options.** `economics.objective_basis` reproduces the
  published totals (`published`) or applies the annualizing factor to both capital terms (`annualized`);
  the traditional design is always recomputed from the current data.
* **Reports are plain pandas/matplotlib** so that notebooks, CLI (`run`, `eval`, `figures`) and tests
  share the same functions.
